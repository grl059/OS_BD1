1. Хэрэглэгчийн заавар

1.1 Програмын зорилго

Linux kernel-ийн өгөгдлийн бүтцүүдийг загварчилж, элемент нэмэх, устгах, хайх үйлдэл бүрийн дараах бүтцийг график дээр харуулна. Бүтцүүд: холбоост жагсаалт (list_head, struct birthday), queue (FIFO), stack (LIFO), bitmap, hash map (collision-той), хайлтын мод (энгийн BST ба тэнцвэржсэн AVL), процесс ба CPU (PCB, ready queue, FCFS ба Round Robin). Kernel module нь struct color жагсаалт болон start параметртэй Collatz жагсаалтыг kernel дотор үүсгэнэ. Хэрэглэгч өөрийн огноо, тоо, түлхүүр, процессоо оруулж туршина.

1.5 Ажиллуулах, зогсоох, reset хийх

  • Веб апп: «Чөлөөт горим» хуудас дээр зүүн талаас бүтцээ сонгоно. «Үйлдэл сонгох» хэсгээс үйлдлээ дарж (жишээ нь add_tail), талбаруудад утга оруулаад «Ажиллуулах»-ыг дарна; команд яг юу болохыг хэсэг дээрх кодын мөрөд урьдчилан харуулна. «Ахисан түвшин: команд шууд бичих» хэсэгт команд (list add_tail 2 8 1995) гараар бичиж болно. «Юу болов?» ба «Түүх (n)» самбар хариу болон ажиллуулсан командуудаа харуулж, «Сүүлчийнхийг буцаах», «Команд хуулах», «Шинээр эхлэх» товч тусална. «Хичээл» хуудсанд Багш алхам бүрт тайлбар хэлнэ (🔊 товчоор монгол дуугаар сонсоно), чи нэг алхамыг нэг удаа ажиллуулж дэвшинэ; дууссан шат ✓-ээр тэмдэглэгдэж браузерад хадгагдана. Хуудсыг дахин ачаалах нь бүх бүтцийг reset хийнэ, учир нь бүтцийн төлөв зөвхөн C программ дотор, дэвсгэр process бүрт шинээр эхэлдэг.
  • CLI: ./kds файл.txt нь script ажиллуулна. ./kds гэж ажиллуулаад команд бичиж болно. Ctrl+D дарж зогсооно (Ctrl+C мөн зогсооно). Програмыг дахин ажиллуулахад бүх бүтэц хоосон эхэлнэ (reset). Бүтэц тус бүрийг list clear, hash clear, sched clear-ээр цэвэрлэнэ. JSON горимоор ажиллуулахад ./kds --json гэж нэмж бичнэ.
  • Kernel module: sudo insmod ачаална, sudo rmmod kds_module буулгана (2.7).

2.7 Kernel module

sh src/kernel/run_module_test.sh
#   make -> docs/kernel_build_log.txt
#   PASS insmod  (start=25, 24 гишүүн)
#   PASS insmod start=15 (18 гишүүн)
#   PASS insmod start=0 (fail: Invalid parameters)
#   -> docs/kernel_dmesg.txt

# Гараар:
cd src/kernel && make
sudo insmod kds_module.ko start=15 && sudo dmesg | grep kds:
sudo rmmod kds_module && sudo dmesg | grep kds: | tail -30

Хүлээгдэх dmesg (start=15): «loading module (start=15)», 4 «color red=… blue=… green=…» мөр, 18 «collatz» мөр (15 46 23 70 35 106 53 160 80 40 20 10 5 16 8 4 2 1), «collatz start=15 terms=18», 5 «birthday d/m/y», «fifo out» 10, 20, 30, «bitmap weight=2, bit15=1». rmmod үед «removing color/collatz/birthday» мөрүүд болон «module unloaded» гарна. start=0 үед «start must be 1..1000000 (got 0)» гарч, insmod амжилтгүй болно.

Secure Boot идэвхтэй үед (insmod: Key was rejected by service) дараах тохиргоог нэг удаа хийнэ:

mkdir -p ~/mok && cd ~/mok
openssl req -new -x509 -newkey rsa:2048 -keyout MOK.priv -outform DER -out MOK.der \
        -nodes -days 3650 -subj "/CN=KDS module signing/"
sudo mokutil --import MOK.der       # reboot хийж, MOK дэлгэц дээр Enroll MOK
# build бүрийн дараа:
sudo /usr/src/linux-headers-$(uname -r)/scripts/sign-file sha256 ~/mok/MOK.priv ~/mok/MOK.der kds_module.ko

MOK.priv түлхүүрийг repository-д хэзээ ч commit хийхгүй (.gitignore-д хассан).

2.9 Known issues

  • Kernel module WSL, Docker-т ачаалагдахгүй (kernel header ба insmod эрх байхгүй). Linux VM эсвэл үндсэн Linux ашиглана.
  • Өөр kernel хувилбар дээр API өөрчлөгдсөн бол module-ийг дахин build хийнэ.
  • CLI-д нэг мөр 1023 тэмдэгтээс урт бол «ERR line too long» гарна.
  • Веб апп серверийн хажуу (web/src/app/api/run/route.ts) C цөмийг дэвсгэр дээр дуудаж ажиллуулдаг тул веб аппыг нээхийн өмнө make-аар ./kds (эсвэл Windows дээр kds.exe) build хийсэн байх ёстой; эс бөгөөс «C core not built» алдаа гарна.
  • Hash-ийн хувьд size 1..16, rehash 1..64 bucket; auto on үед ачаалал 0.75-аас хэтрвэл bucket автомат 2 дахин ихэснэ. Элементийн тоо 24, queue, stack, процесс 8 (дүрслэлд багтаах зорилгоор).
  • macOS 26 + Apple clang: ASan runtime нь програм эхлэх үед төгсгөлгүй хүлээлт үүсгэж болно (гаралтгүй, 100% CPU). Ийм үед make SAN=0 гэж sanitizer-гүй build хийнэ; тест болон веб апп хэвийн ажиллана, зөвхөн ASan/UBSan шалгалт хийгдэхгүй.
